# 本机控制面 · 设计说明

一件产品，三个进程。不是第四个 Agent，也不是四个插件。

## 三进程

1. **签名 Mac 菜单栏助手**（Bundle ID `local.ide-control.helper`）  
   系统设置里出现的就是它。屏幕录制（ScreenCaptureKit）和辅助功能（AXUIElement）只授给它。小原生窗口不抢焦点，订阅同一条时间线。

2. **本机 broker**  
   只听 `127.0.0.1`。每个编辑器窗口一把随机 token。负责会话、允许策略，以及「本地跑命令、本地验收、通过就停」的循环。

3. **VS Code / Cursor 扩展**  
   看得见未保存缓冲区、诊断和集成终端。侧边栏时间线给人回看编程怎么发生。

Linux 开发期用 `npm run helper` 跑演示助手：协议相同，但不是 TCC 主体，也不假装已获系统授权。

## 两项 macOS 授权

- 屏幕录制：默认只订 VS Code / Cursor 窗口，不订整块桌面。帧路径留本机。
- 辅助功能：读控件树、按、设值、输入。

缺授权时助手动词明确拒绝；扩展路径的 edit / terminal / verify 照常。授权四态：`ready`、`missing_screen`、`missing_accessibility`、`missing_both`（另有 `placeholder` / `helper_offline`）。

## 验收循环

模型只交紧凑意图。broker 只跑 `.controlplane/commands.json` 里声明过的命令 id。回执只有退出码、失败名或第一段错误、diff 统计、耗时；verify 再加轮次。完整日志留本机，默认不进模型。通过就停。

## 四个入口

薄适配器，动词同一套：

- Cursor / VS Code：扩展注册 MCP 定义提供者，信任工作区后自动挂上；仍可手抄 `mcp.json`
- Codex：`~/.codex/config.toml` 指向同一 stdio 入口
- DeepSeek Harness：Cordis `dsh-plugin`
- REST：本机 `POST /v1/<动词>`，`entry: "rest"`

未信任的工作区不启动 broker，也不提供 MCP 定义。

## 第一切片动词

`observe` · `edit` · `terminal` · `verify` · `trace` · `observe_ui` · `capture_window` · `perform_ax`

## 反复看，是为了理解编程

时间线记下：谁在下任务、改了什么、命令为何这样跑、验收为何过或失败、这一步走扩展还是走了原生界面。任何代码工作都能调用；STM32 只是「Cursor 下令、VS Code 窗口被看见」的例子，不是插件边界。

## 本机分发包

- **lite**：`npm run pack` → VSIX、CLI、`install.sh`、`dsh-plugin`、Mac 助手源码
- **full**：真机 `mac-helper/scripts/build-app.sh` 打出 `ControlPlaneHelper.app` 后，`npm run pack:full` 或 `npm run compose:full` 合成 `*-full.tar.gz`
- 签名用 `CONTROLPLANE_CODESIGN_IDENTITY`；未签名也可开发安装，但 TCC 授权仍绑 Bundle ID `local.ide-control.helper`
